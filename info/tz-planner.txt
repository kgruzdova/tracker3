Техническое задание
Прогрессивное веб-приложение (PWA) для личного планирования

1. Общее описание проекта

Планировщик — персональное PWA-приложение для личного планирования задач с расширенными модулями:
- голосовые напоминания;
- трекер состояния/баланса (настроение, уровень стресса) с рекомендациями по нагрузке и графиком «настроение / выполненные задачи»;
- встроенный чат-бот для управления задачами обычным языком (без использования GPT).

Продукт предназначен для одного пользователя. Серверная часть не требуется: все данные хранятся локально в браузере, приложение работает офлайн.

2. Цели и задачи

2.1. Цели
- Дать пользователю простой инструмент ежедневного планирования задач.
- Помогать удерживать баланс между нагрузкой и состоянием (настроение, стресс).
- Сократить время на ввод задач — голосовые напоминания и чат-бот.

2.2. Задачи
- Планирование дня: задачи, дедлайны, приоритеты, категории, календарь.
- Ежедневный чек-ин состояния и рекомендации по объёму нагрузки на день.
- Озвучка напоминаний из открытого приложения.
- Управление задачами через чат-бот с распознаванием опечаток.

3. Целевая аудитория

- Самостоятельные специалисты, фрилансеры.
- Студенты и люди с гибким графиком.
- Пользователи с высокой ежедневной нагрузкой, которым важно вовремя отдыхать и не перегружать план.

4. Архитектура и технологический стек

- Тип приложения: SPA + PWA, только клиентская часть, без backend и БД.
- Стек: React + TypeScript + Vite.
- Роутинг: react-router (HashRouter — для корректной работы при раздаче статики и офлайн).
- Хранение данных: localStorage, один версионируемый JSON-объект.
  - Ключ хранилища: planner_db_v1 (с полем DB.version для миграций схемы).
  - Сид-демо-данные для первого запуска (категории, 5-7 задач, чек-ин за 7 дней).
- Оффлайн: manifest.webmanifest + Service Worker (кэширование оболочки приложения и статики).
- Голос: Web Speech API (speechSynthesis) — только на клиенте, без сервера распознавания.
- Тестирование: unit-тесты разбора команд бота и формул рекомендаций.

5. Базовый функционал

5.1. Экран «Сегодня» (Today)
- Приветствие и текущая дата.
- Прогресс дня: «Выполнено X из Y» (полоса прогресса).
- Quick-add: быстрое добавление задачи одной строкой (с авто-разбором даты/времени, если введено).
- Список задач на сегодня: чекбокс, название, время, категория (цветная метка), приоритет.
- Разделители: «В работе», «Просрочено», «Готово».
- Карточка-рекомендация по нагрузке из модуля состояния (раздел 7).
- Кнопка «Отметить состояние» (чек-ин), если за сегодня ещё не отмечено.

5.2. Задачи
- CRUD задач.
- Поля задачи: название; описание; категория; приоритет (высокий/средний/низкий); дата и время (дедлайн); статус (новая / в работе / выполнена / отменена); повтор (разово / ежедневно / еженедельно); создано; обновлено.
- Фильтры: по категории, статусу, приоритету, дате.
- Поиск по названию и описанию.
- Архив выполненных задач (скрытие из активных списков).
- Массовые действия: отметить выполненной, перенести на завтра, удалить.

5.3. Календарь
- Месячный вид с навигацией (предыдущий / следующий месяц, кнопка «Сегодня»).
- На каждой дате — индикаторы: количество задач, выполнена/есть просроченные (цветные точки).
- Клик по дате — список задач этой даты (боковая панель или переход в Today с фильтром).
- Выделение сегодняшнего дня, выходные — отдельным цветом.

5.4. Категории
- Список категорий с цветами и количеством задач.
- Дефолтные категории: Работа, Учёба, Личное, Здоровье, Финансы, Покупки, Дом, Без категории.
- CRUD: создание, редактирование (название, цвет), удаление (с подтверждением; задачи переносятся в «Без категории»).

5.5. Статистика
- Выполнено задач за сегодня / неделю / месяц.
- Серия (streak) дней подряд с выполнением хотя бы одной задачи.
- График выполнения по дням (последние 30 дней, столбчатый).
- Процент выполнения по категориям.

5.6. Профиль и настройки
- Тема: светлая / тёмная (переключатель, системная по умолчанию).
- Экспорт данных в JSON (файл скачивается).
- Импорт данных из JSON (с валидацией и подтверждением замены).
- Очистка данных (с двойным подтверждением).
- Раздел настроек голоса и напоминаний (раздел 6).
- О приложении: версия, краткая справка по командам бота.

6. Голосовые напоминания

Режим работы: голос в открытом приложении (SpeechSynthesis). Push-уведомления и фоновые оповещения — вне объёма MVP.

6.1. Настройки
- Вкл/выкл голосовые напоминания.
- Выбор голоса из списка доступных в системе (фильтр по языку, приоритет ru-RU).
- Скорость речи (0.5x–2x), громкость (0–100%).
- Предупредительный сигнал перед речью (вкл/выкл, выбор звука).
- «Отложить на 10 минут» — повтор напоминания.
- Количество повторов (0–3) с интервалом.

6.2. Механизм работы
- Фоновый таймер в приложении проверяет очередь напоминаний каждую минуту.
- Срабатывание: звуковой сигнал → озвучка текста через speechSynthesis.
- Текст напоминания формируется по шаблону: «Напоминание. {заголовок}. Время {ЧЧ:ММ}» или пользовательский текст.
- Источники напоминаний: время задачи (дедлайн) и отдельные напоминания, привязанные к задаче (за 10/15/30 минут до).
- Журнал сработавших напоминаний (время, текст, результат) — для отладки и раздела «История».

6.3. Ограничения и обработка ошибок
- Отсутствие русского голоса в ОС → фолбэк: текстовое всплывающее уведомление в приложении + звуковой сигнал.
- Автоплей: первая озвучка только после пользовательского взаимодействия (политика браузеров); до этого — предупреждение «Нажмите, чтобы включить звук».
- Нет доступа к API речи (старый браузер) → раздел настроек показывает предупреждение, остальной функционал работает.
- Озвучка не должна блокировать интерфейс (асинхронный вызов, обработка promise-отклонений).

7. Трекер состояния / баланса

7.1. Ежедневный чек-ин
- Настроение: шкала 1–5 с эмодзи и подписями (1 — очень плохо, 5 — отлично).
- Уровень стресса: шкала 1–5 (1 — спокойно, 5 — крайне напряжённо).
- Необязательный комментарий (до 200 символов).
- Один чек-ин в день: повторный ввод за ту же дату перезаписывает запись.
- Отображение: карточка на Today, история за последние 7/30 дней в разделе «Состояние».

7.2. Рекомендации по нагрузке
- Базовая дневная норма: 5 задач (настраивается в Settings).
- Формула: лимит = базовая_норма − поправки, итог в диапазоне 1–7.
- Правила поправок:
  - стресс >= 4 → −2 задачи;
  - стресс = 5 → дополнительно переносим сложные задачи (приоритет «высокий») на завтра;
  - настроение <= 2 → −2 задачи и подсказка «перенеси сложное на завтра»;
  - настроение = 5 и стресс <= 2 → +1 задача («день располагает»);
  - более 2 просроченных задач → −1 задача.
- Результат — текстовая карточка на Today, примеры:
  - «Сегодня стоит запланировать не больше 3 задач»;
  - «Отличное состояние! Можно взяться за что-то сложное»;
  - «Высокий стресс. Оставьте только важное и запланируйте отдых».
- Предупреждение при превышении: если добавлено задач больше лимита, на Today показывается баннер «План на сегодня превышен (X из лимита Y)».

7.3. График «настроение / выполненные задачи»
- Раздел «Состояние»: комбинированный график за 7 / 14 / 30 дней.
- Левая ось: настроение (1–5) — линия.
- Правая ось: выполненные задачи (0–N) — столбцы.
- Подсказки (tooltip) при наведении: дата, настроение, стресс, выполнено задач.
- Легенда, переключение периода, адаптив под мобильный экран (вертикальная ориентация).
- Если чек-ин за день не сделан — точка настроения не рисуется, столбец задач рисуется.

8. Умный чат-бот (без GPT)

Встроенный чат в приложении. Работает на правилах: словари команд, парсер дат/времени, нечёткое сопоставление. Нейросети и внешние API не используются.

8.1. Возможности (намерения)
- Добавить задачу: «добавь задачу купить молоко завтра в 18:00».
- Удалить задачу: «удали задачу купить молоко».
- Изменить задачу: «переименуй задачу в встречу с Анной», «поставь напоминание за 15 минут».
- Перенести: «перенеси отчёт на завтра».
- Отметить выполнением: «отметь задачу отчёт выполненной».
- Показать план: «что у меня на сегодня?», «план на завтра».
- Поставить напоминание: «напомни мне в 17:00 позвонить врачу».
- Статистика: «сколько задач выполнено?».
- Состояние: «как настроение?» / «я настроение 4» (быстрый чек-ин из чата).
- Справка: «помощь», «что ты умеешь?».

8.2. Пайплайн разбора сообщения
1. Нормализация: нижний регистр, удаление пунктуации, стоп-слов («пожалуйста», «ну», «так»), схлопывание пробелов.
2. Определение намерения: словарь синонимов для каждой команды (напр. добавить: «добавь», «создай», «новая задача», «запиши», «внеси»).
3. Извлечение даты: «сегодня», «завтра», «послезавтра», «в понедельник»…, форматы «ДД.ММ», «ДД.ММ.ГГГГ», «через N дней».
4. Извлечение времени: «в 18:00», «в 6 вечера», «полдень».
5. Сопоставление с существующими задачами (для удаления/изменения/выполнения) — по названию.
6. Исполнение действия через общий store приложения, ответ бота с подтверждением.

8.3. Обработка опечаток
- Перед сопоставлением — нечёткое сравнение: расстояние Левенштейна <= 2 слова (или <= 1 для слов <= 4 символов), а также нормализация (ё/е, «и»/«й» на конце).
- Ключевые слова-команды сравниваются с приоритетом: если опечатка в команде («дабавь» → «добавь»), сообщение распознаётся.
- Если после обработки намерение не определено — ровно ответ: «Я Вас не понял» + список из 3–4 примеров команд.
- Никаких «умных» домысливаний: бот не угадывает действие, а просит уточнить.

8.4. Диалоговые состояния (уточнения)
- Несколько подходящих задач: «У меня несколько задач: 1) купить молоко 2) купить хлеб. Какую?» — бот ждёт номер или уточнение.
- Удаление требует подтверждения: «Удалить задачу "купить молоко"? (да/нет)».
- Отмена диалога: «отмена», «хватит» → бот сбрасывает состояние.
- Отсутствие даты при добавлении: «Когда выполнить? (сегодня/завтра/дата)».
- Таймаут состояния: 5 минут без активности → сброс к нейтральному.
- Входные кнопки (quick replies) под сообщением бота: варианты ответа «да» / «нет» / примеры команд.

8.5. Интерфейс чата
- Рроут /app/chat, иконка в навигации.
- Пузыри сообщений: пользователь справа, бот слева; время у сообщения.
- Поле ввода + кнопка отправки; Enter — отправить.
- История диалога сохраняется в localStorage (последние 100 сообщений), кнопка «Очистить историю».
- Кнопка «?» — панель с примерами команд по категориям.

10. Модель данных

DB {
  version: number;
  tasks: Task[];
  categories: Category[];
  moodEntries: MoodEntry[];
  reminders: Reminder[];
  chatMessages: ChatMessage[];
  settings: Settings;
}

Task {
  id, title, description, categoryId, priority ('high'|'medium'|'low'),
  dueDate (ISO), dueTime ('HH:MM' | null), status ('new'|'in_progress'|'done'|'cancelled'),
  repeat ('none'|'daily'|'weekly'), createdAt, updatedAt, completedAt, archived (bool)
}

Category { id, name, color, isDefault }

MoodEntry { date ('YYYY-MM-DD'), mood (1-5), stress (1-5), comment, createdAt }

Reminder { id, taskId | null, text, fireAt (ISO), offsetMinutes, status ('pending'|'fired'|'snoozed'), snoozeCount }

ChatMessage { id, role ('user'|'bot'), text, createdAt, meta (намерение/результат) }

Settings {
  theme ('system'|'light'|'dark'), dailyTaskLimit (default 5),
  voice: { enabled, voiceURI, rate, volume, signal, repeats, offsetMinutes }
}

11. Нефункциональные требования

- Адаптивная вёрстка: от 360 px (мобильные) до 1920 px (десктоп), горизонтальный скролл отсутствует.
- Шрифт Inter (системный фолбэк), читаемые размеры текста от 14 px.
- Светлая и тёмная темы, переключение без перезагрузки.
- Сохранность данных при перезагрузке и офлайне (localStorage + кэш Service Worker).
- Отклик интерфейса: действие < 100 мс (кроме озвучки).
- Код на TypeScript без ошибок типизации; работа latest/предыдущая стабильная версия Chrome, Edge, Firefox, Safari.
- Данные не покидают устройство: никаких сетевых запросов на сторонние сервисы (кроме загрузки собственной статики).

12. Этапы разработки

Этап 1 — Каркас и базовый функционал
- Проект Vite + React + TS, роутер, оболочка, темы, адаптив.
- Store + localStorage + сид-данные.
- Today (прогресс, quick-add, список), CRUD задач, фильтры/поиск.
- Календарь, категории, статистика.
Критерий приёмки: можно планировать день полностью, данные переживают перезагрузку.

Этап 2 — Трекер состояния
- Чек-ин (настроение/стресс/комментарий), история.
- Формула рекомендаций + карточка на Today + предупреждение о превышении.
- Комбинированный график «настроение / выполненные задачи» (7/14/30 дней).
Критерий приёмки: график корректен, рекомендации меняются от значений чек-ина.

Этап 3 — Чат-бот
- Разбор команд, дата/время-парсер, опечатки (Левенштейн), «Я Вас не понял».
- Все намерения из п.8.1, диалоговые состояния, подтверждение удаления.
- UI чата + история + панель примеров.
Критерий приёмки: автотесты на разбор команд (нормальные вводы, опечатки, мусор); все сценарии п.8.1 работают.

Этап 4 — Голосовые напоминания
- Настройки голоса, очередь напоминаний, сигнал → речь, «отложи», журнал.
- Фолбэки: нет RU-голоса, нет speechSynthesis, политика автоплея.
Критерий приёмки: напоминание озвучивается в открытом приложении, фолбэки показывают понятные сообщения.

Этап 5 — PWA и полировка
- manifest.webmanifest, иконки, Service Worker (кэш оболочки), установка на рабочий стол.
- Экспорт/импорт JSON, 404, справка.
- Финальная проверка по чек-листу (п.13).
Критерий приёмки: приложение устанавливается и работает офлайн.

Этап 6 (второй проход, по методичке) — Оформление
- Цвета, иконки, типографика, отступы, микроанимации — после приёмки функциональности.

13. Приёмка MVP (чек-лист)

1. Today показывает прогресс «X из Y» и список задач на день.
2. Задачи создаются/редактируются/удаляются/выполняются, фильтры и поиск работают.
3. Данные сохраняются после перезагрузки (localStorage).
4. Календарь показывает задачи по датам, переход к списку работает.
5. Категории: CRUD и цветные метки в списках.
6. Статистика и streak считаются корректно.
7. Чек-ин: одна запись в день, повтор перезаписывает.
8. Рекомендация по лимиту меняется при стрессе >= 4 и настроении <= 2.
9. Превышение лимита показывает предупреждение.
10. График «настроение / выполненные задачи» рисуется за 7/14/30 дней, есть tooltip.
11. Бот: добавление задачи с датой и временем из текста.
12. Бот: удаление с подтверждением; отмена диалога работает.
13. Бот: опечатка в команде распознается; мусорный ввод → «Я Вас не понял» + примеры.
14. Бот: уточнение при нескольких совпадениях задач.
15. Голос: настройки (голос, скорость, громкость) сохраняются.
16. Голос: напоминание озвучивается при открытом приложении; «отложи» работает.
17. Отсутствие RU-голоса → текстовое уведомление вместо ошибки.
18. Экспорт/импорт JSON без потери данных.
19. Тема light/dark переключается, адаптив 360–1920 без горизонтального скролла.
20. PWA: установка на рабочий стол, офлайн-запуск, manifest и Service Worker активны.

Исключения из объёма MVP:
